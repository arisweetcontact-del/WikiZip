# tiny-rag (NOT USEABLE YET! WILL FAIL IF RUN)

A tiny local question-answering setup that runs on 8GB of RAM, no GPU.

**The idea:** your reference material sits zipped. A small
keyword index (a few KB) tells the system which zip is relevant to a
question. nothing is unzipped permanently. When you ask something, only
the matching zip(s) get read into memory, their text is handed to a small
local language model (served by [Ollama](https://ollama.com)) as context,
and the model answers from that. The "knowledge" stays compressed on disk
until it's actually needed.

```
tiny-rag/
├── knowledge/        # your .zip files go here (each one = a topic/source)
├── src/
│   ├── ingest.py      # builds the tiny keyword index
│   ├── ask.py         # answers a question using the index + Ollama
│   └── common.py
└── index.json         # generated by ingest.py
```

## Setup

1. **Install Ollama** — a standalone app that runs small local models, no
   Python packaging involved:

   - Download from https://ollama.com/download (macOS installer), or
   - `brew install ollama` if you use Homebrew

   Either way, it installs a background service listening on
   `localhost:11434` and starts automatically.

2. **Pull a small model.** For 8GB RAM, this one is a good default (~1GB
   download, fast on CPU):

   ```
   ollama pull qwen2.5:1.5b
   ```

   Even tighter on RAM? Try `ollama pull qwen2.5:0.5b` instead (~350MB)
   and change `OLLAMA_MODEL` at the top of `src/ask.py` to match.

3. **Add your own material.** Replace or add to the example zips in
   `knowledge/` — each zip should contain `.txt` or `.md` files. One zip
   per topic/source works best (e.g. `onboarding-notes.zip`,
   `project-x-notes.zip`), since a whole zip is what gets pulled in per
   match.

4. **Build the index** (re-run this any time you change `knowledge/`):

   ```
   python3 src/ingest.py
   ```

5. **Ask something:**

   ```
   python3 src/ask.py "when does badge access get set up?"
   ```

   You'll see which zip(s) it decided were relevant and unzipped, followed
   by the model's answer.

No `pip install` needed anywhere — `src/` uses only Python's standard
library, and Ollama handles the model.

## How it stays tiny

- **The model** is a small quantized model (~350MB–1GB), managed entirely
  by Ollama — no GPU, no compiling, no large manual download.
- **The knowledge base** stays compressed. `ingest.py` reads each zip
  once, in memory, to build a lightweight word-frequency index (a JSON
  file, typically a few KB even for a large knowledge base, then
  discards the extracted text. Nothing is left unzipped on disk.

**At query time**, only the top 1–2 matching zips are opened (still in
  memory, via Python's `zipfile`, never extracted to disk) and their text
  becomes the model's context for that one answer.
